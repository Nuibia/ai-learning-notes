# 重启恢复后的有效上下文

这是为 L11「上下文、Token、成本与延迟」补充的独立工程证据。场景是：会话在用户确认写入前重启，Runtime 要从持久化状态恢复，并判断哪些信息值得作为下一次模型调用的上下文。

运行：

```bash
node examples/2026-07-27-context-selection-evidence/demo.mjs
```

## 它验证什么

- Runtime 恢复完整状态：会话 ID、阶段、待执行动作、幂等键与上次执行结果；
- 在本题设定中进入模型上下文：当前约束、当前目标、`waiting_confirmation` 状态、待执行意图、该意图是否已执行；
- 在本题设定中排除无关旧闲聊；
- 原始幂等键用于 Runtime 防止重复执行；其语义结果（例如“尚未执行”）可在需要时成为 LLM 的有效上下文。
- 哪些状态要传给模型，仍取决于实际 Runtime 和本次任务。

## 证据边界

这里的“token 权重”是确定性示例，不是某个真实模型 tokenizer 的计算结果。Demo 是 AI 生成并由机器执行的工程验证，供学习者审查；它不替代学习者已有的上下文工程经验。
